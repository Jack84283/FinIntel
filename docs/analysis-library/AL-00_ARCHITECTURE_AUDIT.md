## Numerical reuse and source restrictions

| Existing entry point | Semantics to preserve | Planned reuse or gap |
| --- | --- | --- |
| `validated_observations`, `compute_series` | Positive finite decimal closes, unique increasing actual dates, daily frequency, windows restricted to 5, 10, 14, 20, 21, 50, 63, 126, 200, 252. Daily simple return is `P(t) / P(t-1) - 1`, first return is null. Decimal prices and price ratios precede the float boundary for logarithms/statistics. | Use the validated series and published units. A model needing other windows needs a separately bounded contract without widening the current analytics API. |
| `compute_series` SMA and momentum | SMA is the trailing W closes and warms up at W closes. Momentum is `P(t) / P(t-W) - 1` and warms up at W+1 closes. | Reuse momentum for 21/63/126/252 intervals and report both observation dates. Regime can build on SMA50/200. Add EMA seeded by the first W closes' SMA, with causal updates, warm-up nulls, and explicit equality and crossover rules. |
| `compute_series` RSI | Simple rolling W close differences, `100 × gains / (gains + losses)`, flat window = 50. W+1 closes required. | Add descriptive thresholds around this output. Preserve simple rolling RSI and version the classification boundaries. |
| `compute_series` volatility and `_drawdown_recovery` | Sample standard deviation of W observed simple returns × √252, W+1 closes required. Drawdown is close/running peak − 1. Peak history starts at the first selected close. Recovery is first observed close at/above peak. Unrecovered durations are right-censored, with null recovery date and interval lengths. | Reuse volatility and drawdown for risk and volatility for regime. Preserve actual dates and current versus maximum drawdown, and distinguish underwater sessions from completed recovery duration. |
| `compare_series`, `run_index_basket` | Relative strength is the ratio of normalized level paths from the first common close. Rolling Pearson correlation uses paired returns on consecutive common dates, requires W paired returns, and is null for zero variance. Pairwise strict mode refuses date mismatches. Basket metrics use the intersection across all sources. | Reuse the pairwise or basket path as appropriate. Keep relative-strength ratios and percentage returns in separate fields. Preserve baseline orientation, original source counts and each hash. Consecutive aligned dates can span multiple exchange sessions. |
| `evaluate_builtin_indicator`, `_sma` | `builtin.sma_crossover@1.0.0`, revision `sma-crossover-observed-close-v1`, uses its existing 28-digit decimal SMA serialization. Fast 2–100 (default 5), slow 3–252 (default 20), fast < slow. Whole-run minimum is slow+1 observed closes, while the first point with both averages is available at slow closes. Fast strictly above slow gives long, equality and below give flat, warm-up gives null. | Preserve the SMA evaluator's values, after-close timing, identifiers, hashes and wire format. Protect existing output with golden and compatibility fixtures before sharing any implementation detail. |

Generic analytics accepts explicitly identified raw-unadjusted daily equity closes as well as FRED daily indexes. Its explicitly enabled VIX level-change option remains part of that analytics contract. Initial research eligibility is narrower: only FRED SP500, DJIA, NASDAQCOM and NDX, with `instrument_kind=index`, `adjustment=price_index`, `return_semantics=price_index`, `frequency=daily` and `units=index_points`. This excludes VIX as a conventional return input, provider mixing, inferred memberships, adjusted/total-return coercion and synthetic dates. FRED price-level returns omit dividends and express hypothetical index research.

`require_complete` requires a completed, non-stale scan that matches the current quality source version and UTC validation date, with zero active unresolved findings for the selected codes. `allow_unverified` bypasses that requirement while still recording the actual verification outcome. The SMA evaluator warns only when `quality_verified=false`. Phase 2C1 requires `quality_verified=true` and a null quality warning, so verified output can meet its quality checks even when the request used `allow_unverified`. Design v1.0 proposes excluding all override-policy results from verified backtests. AL-07 must version that stricter eligibility rule at the durable backtest boundary and test both a verified override result and an unverified override result, while preserving the existing pure Phase 2C1 behavior. [Index analytics contract](../INDEX_ANALYTICS.md)

The current source snapshot SHA-256 covers kind, code, provider, adjustment, and return semantics, followed by each selected row's session date, close, and `retrieved_at` in date order. Frequency and units are validated separately. The digest excludes rows outside the selection, catalog coverage metadata, ingestion-run observation and payload hashes, and quality scan evidence. A new import can create an ingestion-run revision while preserving unchanged close rows and their retrieval timestamps. Quality currency is checked independently and can change while the selected-row digest stays stable. Completed jobs retain their original stored lineage. [Index ingestion](../../backend/finintel/market_data/index_history.py)

The managed sidecar binds to loopback and uses its per-process token. The synchronous evaluator and job endpoints require managed authorization. Keep job input validation errors redacted and child requests limited to an allowlisted job ID and attempt. Existing browser, native and Python contracts hardcode the SMA shape in different places. Extend them together at the appropriate phase. Existing desktop SMA verification independently checks reported averages and canonical hashes in [`model-research-integrity.ts`](../../apps/desktop/src/model-research-integrity.ts). New analysis views should validate transport, identity, and integrity while consuming precomputed Python metrics.

The separate jobs SQLite ledger uses schema v1 with canonical request hashes, stable job IDs, a mandatory source snapshot pin, bounded results, progress, and timestamped status. Claim is atomic and writes are fenced by attempt generation. Queued cancellation is immediate, running cancellation uses a request flag, and retry reuses the original request. Startup reconciliation under the supervisor lock fails or cancels interrupted running jobs and preserves the queue. A child checks its pin before and after evaluation, and the evaluator also checks the pin on its own read. On detail retrieval the ledger validates stored identity/lineage and digests, without reopening the current market data to reinterpret old results. Limits remain one subprocess, 32 active jobs, three attempts, 90 seconds, 2,000 observations and 4 MiB retained result. Memory controls vary by OS. [Ledger](../PRIVATE_MODEL_JOBS_LEDGER.md) · [Worker](../PRIVATE_MODEL_JOBS_WORKER.md)

SMA `model-research-evaluation-v1` hashes the sorted compact JSON lineage and ordered points separately using SHA-256. The audit timestamp is outside both digests. The evaluator's `persistent_job=false` and `backtest_validated=false` are part of the existing result shape, including when an evaluation is retained in a job. Keep legacy readers and values, including the calculation and implementation revision of prior outputs. A new envelope should explicitly pin model ID/version/revision, parameter schema, source identity and each snapshot hash, requested and observed dates, quality policy and state, warnings, point/output schema and units, after-close availability, calculation/evidence versions, and canonical result digest. Define the exact stable payload and serialization and exclude evaluation timestamps. Separate catalog metadata for proposed models from the executable allowlist. [SMA contract](../PRIVATE_MODELS_V1.md)

Phase 2C1 accepts only source-pinned, verified-quality SMA research. It independently re-derives causal SMA and signals from the supplied closes but has no live database verification or job persistence. Its train end is the observed predecessor of test start, the test contains at least two observed sessions, and parameters are fixed. A signal at t can change hypothetical exposure at the next observed close only. Prior exposure earns the interval ending at that close. Costs apply on turnover, and the comparison is a same-index, frictionless price benchmark. Durable integration must revalidate local source and model contracts, preserve frozen evidence, and retain Phase 2C1 numerical results. Descriptive risk, RSI or regime states confer no backtest strategy eligibility. [Phase 2C1](../BACKTEST_PHASE_2C1.md) · [PR #70](https://github.com/Jack84283/FinIntel/pull/70)

## Proposed modules and compatibility gates

Keep generic primitives and source adapters in `market_data/analytics*.py`. Keep versioned evaluators in `models/`, with narrow `trend.py`, `risk.py` and `regime.py` modules if the implementations warrant them. Extend the current registry, ledger, supervisor, and fixed API/IPC paths in place. Keep the pure simulator in `models/backtest.py`. Use a typed adapter at the job boundary so worker dispatch and stored readers can evolve independently of the simulator and legacy SMA payload.

- **Versioning and arithmetic.** Preserve public `index-analytics-v2` and SMA hashes, signal timing, nulls and precision. Use explicit schema/version dispatch for legacy jobs and results. Establish frozen deterministic fixtures, including both legacy wire validation and exact hash reproduction before extracting shared code.
- **Quality and source revisions.** Keep the default quality gate and explicit override. Test stale/missing/partial findings, selected-row changes, metadata-only ingestions, unsupported VIX/provider semantics, malformed observations and incomplete history. For AL-05 and AL-07, explicitly declare whether the pin covers selected rows only or adds ingestion metadata under a new evidence contract. Recheck quality separately from digest equality. Maintain the distinction between historical job integrity and verification of the current source for a new run.
- **Durable jobs and storage.** Test queue, cancel/retry, stale attempt completion, corruption, restart and source changes during execution. If new fields require a schema change, use an additive migration on the job ledger with upgrade, rollback/interruption and restart fixtures using disposable databases. Keep observations, backups, revisions, audit findings and prior job records intact. Share no private inputs, outputs or credentials through logs, GitHub or CI artifacts.
- **Native and worker bounds.** Keep the current fixed command allowlist, token requirements, one-child supervisor, bounded payloads, and no provider requests during analysis. Retain offline operation and document resource costs before proposing any cap change.
- **UI and acceptance.** Reuse freshness fences from [PR #68](https://github.com/Jack84283/FinIntel/pull/68) and [PR #69](https://github.com/Jack84283/FinIntel/pull/69). Verify chart/table agreement, unknown/warm-up and blocked states, bilingual copy and keyboard access with mounted tests. Installed desktop, authorized provider spot checks, private data performance, and backup/restore acceptance are separate owner gates performed on disposable copies.
