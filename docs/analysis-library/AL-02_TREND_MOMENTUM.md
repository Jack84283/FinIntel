# AL-02 · Trend and Momentum models

AL-02 adds four historical price-index research models using the [AL-01 contracts](AL-01_MODEL_CONTRACTS.md) and [Analysis Library Design v1.0](https://docs.google.com/document/d/1VAZkbr28W_E7IKpbOLGjkRoZeyjE4CNt/edit). The v2 registry lists these models as proposed. An internal Python evaluator reads pinned local snapshots for numerical use and validation. The existing SMA evaluator, HTTP execution routes, durable worker, job store, desktop, and Phase 2C1 backtest retain their existing contracts.

| Model | Implementation revision | Parameters and minimum history |
| --- | --- | --- |
| `builtin.ema_trend@1.0.0` | `ema-sma-seed-decimal-v1` | Fast 12 by default (1–1,999) and slow 26 by default (2–2,000). Fast must be strictly less than slow. The request needs at least slow-window observations. |
| `builtin.momentum@1.0.0` | `momentum-trailing-observed-v1` | Lookback of 21, 63, 126, or 252 observed intervals, with 63 as the default. The request needs lookback plus one close. |
| `builtin.relative_strength@1.0.0` | `relative-strength-common-baseline-v1` | Two to four distinct sources and at least two shared observations. The first requested source is the benchmark. Source order is significant. |
| `builtin.rsi_state@1.0.0` | `rsi-simple-rolling-states-v1` | Window 14 by default (1–1,999). Integer thresholds from 0 through 100 default to 30 and 70, with lower strictly less than upper. One observation is sufficient for an explicitly warming-up result. |

## Numerical conventions

- **EMA.** Seed each EMA separately with the arithmetic mean of its first N actual closes, computed as the first close plus the mean of the deviations from it to preserve constant levels at the selected precision. Then update it using previous EMA plus 2/(N+1) times the difference between current close and previous EMA. A one-observation EMA is the closing level at the calculation precision. Each EMA is null before its seed. The difference is fast EMA minus slow EMA and remains null until both exist. Persistent state is `above`, `below`, or `flat` on equality. Upward cross means the previous comparable difference was zero or negative and the current difference is positive. Downward cross is the inverse. A row with both EMAs but no transition emits `none`, including the first comparable row. Warm-up emits a null state and event. Both are available only after the observed close.
- **Momentum.** At observation t, divide its level by the level exactly N observed intervals earlier and subtract one. The first N rows have null comparison dates, comparison levels, and returns. Later rows include the actual comparison session and level. Returns describe historical price-index changes, with dividends excluded.
- **Relative strength.** Intersect actual dates across the entire basket. For source i, divide each close by its first shared close to get the growth factor. Normalized performance is 100 times that factor. Relative strength is the source growth factor divided by the benchmark growth factor. The return difference subtracts the benchmark's cumulative decimal return from the source's cumulative decimal return. For example, 10% versus 5% has return difference 0.05 and ratio 1.10/1.05. Benchmark rows have ratio one and difference zero. The v1 basket's existing left-over-right convention is preserved on that surface. The new model's fixed output schema has one set of fields per eligible code, null for absent codes. The row's `benchmark` uses the lowercase code, and the first evidence pin contains the full benchmark identity. Each source's evidence reports its common and excluded observation counts and original window.
- **RSI.** Reuses the `index-analytics-v2` simple rolling gains and losses calculation. RSI is 100 times the sum of gains divided by the sum of gains and absolute losses over N observed changes. A flat window gives 50. The first N values and classifications are null. RSI at or below the lower threshold is `low`, at or above the upper threshold is `high`, and otherwise is `neutral`. The states are descriptive.

AL-02 computes with 28 significant Decimal digits and round-half-to-even. It serializes Decimal results in fixed-point notation. Closing levels retain their stored numeric value. All index levels and moving averages are positive. Derived decimal returns and differences can be negative. Fixed-point fields exceeding 256 characters and envelopes exceeding 4 MiB fail explicitly. The observation cap is 2,000 per selected source before alignment, and the result has at most 2,000 rows. No model creates dates, interpolates missing data, sees future prices, or forecasts prices.

## Source evidence and AL-05 integration

- Eligibility is restricted to daily FRED SP500, DJIA, NASDAQCOM, and NDX price-index levels. Each requested pin binds the complete AL-01 identity and the existing selected-row snapshot SHA-256. The digest covers selected row dates, closing levels, and retrieval timestamps with the stored source identity. See [AL-00](AL-00_ARCHITECTURE_AUDIT.md) for ingestion revisions and quality currency.
- One read-only SQLite transaction loads and checks every source before calculation. A mismatched identity, changed pin, invalid price or date, or inadequate history fails explicitly. Observations, revisions, and backups are never modified. Normalization, RSI, the simple return formula, and overlap alignment share existing analytics primitives.
- The default quality policy checks each source against the current complete scan. `allow_unverified` records `quality_override` at the result level and retains each source's actual quality status and warning. Evidence distinguishes scans that have never run, current partial scans, stale scans, completed scans with unresolved findings, and verified sources. Existing analytics responses retain their combined stale-or-partial status. The evaluator preserves the requested range, ordered source pins, actual sessions, resolved parameters, schemas and units, and passes the produced envelope through the registry's result binding.
- AL-05 should use the existing sidecar and worker boundaries to resolve and pin sources before scheduling, then recheck pins and quality before evaluating under a closed allowlist. The internal entry point is `evaluate_trend_model(AnalysisRequest)`. Its input and output remain independent of the legacy SMA wire format. Confirm the aggregate multi-source work budget and the existing worker limits before granting managed execution. Persist the versioned result and its evidence, and revalidate it on retrieval.
